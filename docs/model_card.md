# Model card: DGA domain classifier (`dga-lightgbm-0.3.0`)

| | |
|---|---|
| Task | Is one DNS query name generated by a DGA? (PS class c) |
| Model | LightGBM `LGBMClassifier` (120 trees, learning rate 0.08, 15 leaves, min 5 samples/leaf, seed 26145) + Platt calibration |
| Status in the pipeline | **Shadow** (`config/thresholds.yaml` `dga.model_mode: shadow`): scores every DNS query, probability recorded in `evidence.model`; the rule detector decides |
| Code | `models/dga_model.py`, `models/dga_dataset.py`, `detectors/dga.py`, `scripts/train_eval_dga.py` |
| Artifact | `models/artifact/dga_lightgbm.txt` (text booster) + `dga_model_meta.json`; gitignored, SHA-256 in `benchmarks/dga_eval_20260924T191002Z.json`. No pickle: loading never executes artifact code |
| Fallback | No artifact or no `lightgbm` installed -> rules only |

## Inputs (7 lexical features, from the query name only)

`length`, `entropy`, `digit_ratio`, `vowel_ratio`, `label_count`, `lm_bigram`, `lm_trigram` (character n-gram scores against a
benign language model), in the frozen order of `features/feature_order.py`.
Nothing from a response or a label is used: `nxdomain_rate` was removed in task 1 because v0.1 filled it from the training label.
NXDOMAIN evidence is still used by the burst rule in `detectors/dga.py`, from observed responses.

## Training data

* Benign: 1,395 synthetic names from 46 vocabulary words (20 more words held out entirely for testing) **plus 6,000 real
  domains** from one half of the Tranco top-30,000 list (hash split by domain; list sha256 `e60e32c9...`).
* DGA: 1,484 synthetic names from 5 generic DGA styles written locally (numeric_seed, hexflux, wordmix, dictcat, base32); they are not copies of DGArchive families. No real DGA samples.
* The benign n-gram model is built from training benign names with out-of-fold scores, so no name is scored against its own n-grams.
* The deployed artifact is refit on all of the above after evaluation.

## Evaluation (`benchmarks/dga_eval_20260924T191002Z.md`, threshold 0.5)

| Test set | Result |
|---|---|
| Grouped validation (in-vocabulary, no registered domain on both sides) | DGA P 1.000 / R 0.937; benign R 1.000; ROC-AUC 1.0, Brier 0.023 |
| Synthetic benign built only from **held-out words** (551) | 0 false positives |
| **Real** benign, disjoint Tranco half (15,103 never trained on) | **0.98 % false positives (148)** - rules: 0.05 % at 0.85, 0.25 % at 0.70 |
| Leave-one-family-out DGA recall | numeric_seed 0.98, hexflux 1.00, wordmix 0.55, **dictcat 0.00**, base32 0.50 |
| Rules fallback, same folds | 0.80, 0.77, 0.13, 0.00, 0.83 |

History (same script): trained on synthetic benign only, the model flagged **11.7 %** of the real Tranco top-10,000
(`dga_eval_20260924T184620Z.md`) - it had learned our generator's vocabulary. Adding real benign names cut that about 12x,
and also showed that unseen word-based families look benign once real names are in training.

## Why it is in shadow

Switching rule: turn it on only when its false-positive rate on held-out real domains beats the rules' and unseen-family recall
stays high. It does not yet (0.98 % vs 0.25 %). No threshold was tuned on test data.

## Known limits

* DGA side is synthetic; real DGA recall is unmeasured (DGArchive not used).
* Remaining real false positives are short or unusual brand names (e.g. `quickconnect.to`, `imrworldwide.com`).
* Word-based DGAs (dictionary concatenation) are the weakest case for both the model and the rules.
* Cost: shadow scoring runs per DNS query; the 10,000 events/s benchmark still passes (CPU 91 %, `throughput_20260924T185020Z.md`).

## Reproduce

```
python scripts/train_eval_dga.py --save-model --real-benign intel/tranco/top-1m.csv --train-real --real-top 30000
```
(Download the Tranco list to `intel/tranco/` first; it is gitignored.)
